# Day 66 · 포트원 승인 웹훅

[공개 앱](https://food-community-nine.vercel.app)에 `0a35456`을 [배포](../deploy.md)했다. 기존 테스트 웹훅 주소와 서명 키를 유지한다. `Transaction.Paid`는 포트원 단건 조회로 승인과 주문을 대조한 뒤 기존 RPC를 호출한다. 같은 주문에 웹훅과 브라우저 확인이 동시에 도착해도 결제와 스냅샷은 한 쌍만 저장된다. 전체·부분 취소 처리는 그대로다. 원격 DB에 승인·취소 RPC가 이미 있어 추가 마이그레이션은 없다.

로컬에서 단위 테스트 100개, 전체 스택 테스트 96개와 린트를 통과했다. [웹훅 통합 테스트](../../tests/e2e/payment-webhook.test.ts)는 완료 화면을 거치지 않고 승인 웹훅을 동시 전송하고 재전송한다. 잘못된 서명, 금액과 거래 번호 불일치, 승인 뒤 취소도 확인한다.

공개 앱에서 서명 없는 웹훅은 `401`을 반환했다. Ego 테스트 주문의 결제와 스냅샷은 승인 전 모두 0건이다. 실제 포트원 테스트 결제 승인을 기다리는 중이다.

## 공개 앱에서 재현

1. Ego CLI로 로그인한 상품 페이지에서 테스트 주문을 준비한다. 해당 주문의 결제·스냅샷이 0건인지 확인한다.
2. 상품 페이지에서 포트원 테스트 결제창만 열고 사용자가 카드를 승인한다. SDK 복귀 주소를 상품 페이지에 두고 `/complete` 접근과 `/api/payments/confirm` 호출이 없음을 확인한다.
3. 포트원 단건 조회에서 테스트 채널의 `PAID`와 승인 웹훅 전달 성공을 확인한다. Supabase에서 해당 거래의 승인과 스냅샷이 각각 1건인지 확인한다.
4. 포트원에서 같은 승인 웹훅을 재전송한다. Supabase에서 건수와 두 레코드의 ID가 그대로인지 확인한다.
5. 해당 테스트 거래만 전액 취소하고, 기존 취소 웹훅으로 마이페이지에 취소 내역이 한 건 생겼는지 확인한다.
