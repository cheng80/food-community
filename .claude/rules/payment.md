# 결제 규칙

결제 기능의 기준 문서다. 적용 경로: 상품 조회, 결제 준비·확인, 결제 내역, 이후 웹훅·환불.

- Day 64는 포트원 V2 카드 **테스트 채널**만 사용한다. 테스트 기록은 실제 신청·정산에 쓰지 않는다. 상점 ID·테스트 채널 키·V2 API Secret은 환경변수에서 읽고 서버 키와 비밀은 브라우저·로그에 노출하지 않는다.
- 공개 상품과 연결된 이미지 경로만 노출한다. 결제 시작 시 인증과 공개 여부를 확인하고, 서버가 상품명·원화 금액·UUID를 정한다. 상품 가격·사용자·상품 스냅샷은 주문 준비 시점에 고정한다. 포트원에도 금액을 사전 등록한다.
- 브라우저 성공 신호와 리다이렉트는 확인 요청의 계기다. 서버가 결제 소유권을 먼저 확인한 후 포트원 단건 조회로 `PAID`, ID·상점·테스트 채널·카드·KRW·금액·상품·회원이 모두 일치하는지 대조한다. 간편결제 응답은 실제 수단이 카드로 확인될 때만 인정한다.
- 검증된 승인만 서버가 스냅샷과 함께 원자적으로 추가한다. 같은 `paymentId` 재확인은 기존 승인을 반환한다. 스냅샷은 당시 표시용 정보만 보관하고 카드 번호·승인 번호·연락처·PG 응답 원문은 저장하지 않는다.
- 결제 이력과 스냅샷은 append-only다. 취소는 PG 확정 후 원승인과 동일한 거래 키, 고유 취소 이벤트 키, 음수 금액으로 추가한다. 중복 이벤트를 무시하고 승인 총액을 넘는 환불을 막는다. 실패나 취소 요청만으로 음수 행을 만들지 않는다. 재결제는 새 거래 키를 쓴다.
- 승인·취소 웹훅은 원문 서명과 전송 시각을 검증한다. `Transaction.Paid`는 포트원 단건 조회로 주문·테스트 채널·거래 번호를 대조한 뒤 브라우저 확인과 같은 RPC로 승인과 스냅샷을 저장한다. 이미 저장한 승인 재전송은 처리 완료로 응답한다.
- 취소 웹훅은 같은 대조를 거쳐 확정 취소만 반영한다. 취소가 승인 확인보다 먼저 오면 검증된 승인과 취소를 함께 저장한다. 취소 요청 API는 제공하지 않는다.
- 운영 채널로 전환하기 전 정원 경쟁과 중복 신청 방지, 환불·회원 탈퇴 정책, 구매자 정보 처리 방식을 확정한다.
